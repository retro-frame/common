1. INTRODUCTION

1.1 Background
-------------------------------------------------------------------------------

[RETRO-FRAME] is a Retro-Endeavor that provides common documentation (i.e.
definitions, guidelines, templates and generic specifications, covered by this
repository) as well as topic-related specifications (covered by individual
repositories) which are intended for use in retrospective programming and may
be used as a whole or partially for other purposes.

As Retro-Frame is evolving, declarations of compliance should always refer to
a specific release version of this repository (i.e. the common documentation).
If a general intention of compliance is expressed, a reference to the major
version may be given by "Retro-Frame 1.x". However, an actual reference should
specify the minor version as well (e.g. "Retro-Frame 1.1").

Note that the individual topic-related specifications (e.g. a data format)
use independent version numbers and the repositories may have different minor
versions than the Retro-Frame Common Documentation respository.


1.2 Scope
-------------------------------------------------------------------------------

This document provides a SPECIFICATION of the textual representation of binary
values which may be used to transmit, identify or verify arbitrary sequences of
bits using language rather than digits.

2. TRBV WORD LISTS
===============================================================================

TRBV specifies two separate word lists, one consisting of 4-letter words and
the other one consisting of 5-letter words.

Each word differs from all other words on at least two positions. Words with a
similar pronunciation have been avoided. However, a "phonetic distinctiveness"
like the [PGP WORD LIST] is not achieved.

The 5word list may be divided into two sub-lists: If the least significant bit
is set to 0, the resulting sub-list maps each 8-bit value to a 5-letter-word
(i.e. columns + 0x0, + 0x2, + 0x4 and + 0x6) and is called 5wordL. Accordingly,
if the least significant bit is set to 1, the resulting sub-list maps each
8-bit value to a 5-letter-word (i.e. columns + 0x1, + 0x3, + 0x5 and + 0x6),
which is different from each word in the other sub-list, and is called 5wordH.



3. TRBV PATTERN
===============================================================================

TRBV specifies 4 patterns which represent a sequence of 4-letter respectively
5-letter words from the two word lists 4word and 5word.


3.1  8-bit pattern
-------------------------------------------------------------------------------

An 8-bit value is represented by one 4-letter word, i.e. the following pattern:

  4word

The resulting pattern has a length of 4 characters.


3.2 16-bit pattern
-------------------------------------------------------------------------------

A 16-bit value is represented by two 5-letter words according to the following
pattern:

  5wordL-5wordH

The first word is determined by the high 8 bits of the value using the sub-list
5wordL while the second word is determined by the low 8 bits of the value using
the sub-list 5wordH.

Both words are separated by a hyphen-minus '-'. The resulting pattern has a
length of 11 characters.


3.3 32-bit pattern
-------------------------------------------------------------------------------

A 32-bit value is represented by a mix of two 5-letter words and two 4-letter
words according to the following pattern:

  5wordH-5wordL-4word-4word

The first word is determined by the highest 8 bits of the value using the sub-
list 5wordH while the second word is determined by the following 8 bits of the
value using the sub-list 5wordL. The last two words are determined by the next
to lowest followed by the lowest 8 bits of the value using the word list 4word
in both cases.

All words are separated by a hyphen-minus '-'. The resulting pattern has a
length of 21 characters.


3.4 64-bit pattern
-------------------------------------------------------------------------------

A 64-bit value is represented by a mix of four 5-letter and three 4-letter
words, where the pattern depends on the highest 4 bits of the value according
to the following table:

  value  pattern
  -----  -----------------------------------------   
  0x0    4word-5word-4word-5word-4word-5word-5word
  0x1    4word-5word-4word-5word-5word-4word-5word
  0x2    4word-5word-4word-5word-5word-5word-4word
  0x3    4word-5word-5word-4word-4word-5word-5word
  0x4    4word-5word-5word-4word-5word-4word-5word
  0x5    4word-5word-5word-4word-5word-5word-4word
  0x6    4word-5word-5word-5word-4word-4word-5word
  0x7    4word-5word-5word-5word-4word-5word-4word
  0x8    5word-4word-4word-5word-4word-5word-5word
  0x9    5word-4word-4word-5word-5word-4word-5word
  0xA    5word-4word-4word-5word-5word-5word-4word
  0xB    5word-4word-5word-4word-4word-5word-5word
  0xC    5word-4word-5word-4word-5word-4word-5word
  0xD    5word-4word-5word-4word-5word-5word-4word
  0xE    5word-4word-5word-5word-4word-4word-5word
  0xF    5word-4word-5word-5word-4word-5word-4word

The first word is determined by the highest 8 or 9 bits of the value after the
4 bits which determine the pattern (see above). The next word is determined by
the following 8 or 9 bits and so on.

All words are separated by a hyphen-minus '-'. The resulting pattern has a
length of 38 characters.



4. TRBV MODES
===============================================================================

The TRBV modes determine how a value of arbitrary maximum size is represented
by TRBV words. While the maximum size is unlimited, modes may require a minimum
size. It is also possible to process an arbitrary sequence of bytes, which must
be 8 bits each, by considering the sequence as a single value in big endian
representation (note that is not required to know the total size in advance but
in this case the size shall be a multiple of 8 bits as zero bit padding is only
allowed if it does not alter the value).

Note that the different modes always produce different sequences of words (i.e.
it is impossible that two different modes produce the same result) and that the
mode always can be determined by the first two words (if given).


4.1 8-bit mode
-------------------------------------------------------------------------------

The 8-bit mode does not requires a minimum value size. If the value hat less
than 8 bits, zero bits are prepended.

In the 8-bit mode, the value is represented by a sequence of 8-bit patterns,
from the most significant bits to the least significant bits.

All patterns are separated by a hyphen-minus '-'. The resulting sequence of
words has a length of (n * 5) + 4 characters.

The resulting sequence of words consists of 4-letter words only. Thus, each
TRBV sequence of words which consists of a single 4-letter word or starts with
two 4-letter words can be identified as 8-bit mode.


4.2 16-bit mode
-------------------------------------------------------------------------------

The 16-bit mode requires a minimum value size of 9 bits. If the value hat less
than 16 bits, zero bits are prepended.

In the 16-bit mode, the value is represented by a sequence of 16-bit patterns,
from the most significant bits to the least significant bits. If there are only
8 bits left in the value, the 8-bit mode is used for the remaining bits.

All patterns are separated by a hyphen-minus '-'. The resulting sequence of
words has a length of (n * 12) + 11 characters.

The resulting sequence of words consists of 5-letter words only except the last
word which may be a 4-letter word. There will never be a repeating word. Each
TRBV sequence of words whose first two words are 5-letter words and the very
first word is from the sub-list 5wordL can be identified as 16-bit mode.


4.3 32-bit mode
-------------------------------------------------------------------------------

The 32-bit mode requires a minimum value size of 17 bits. If the value hat less
than 32 bits, zero bits are prepended.

In the 32-bit mode, the value is represented by a sequence of 32-bit patterns,
from the most significant bits to the least significant bits. If there are less
than 32 bits but at least 16 bits left in the value (i.e. 24 or 16 bits), the
16-bit mode is used for the remaining bits. Otherwise, if there are only 8 bits
remaining, the 8-bit mode is used.

All patterns are separated by a hyphen-minus '-'. The resulting sequence of
words has a length of (n * 22) + 21 characters.

The resulting sequence of words always consists of 5-letter and 4-letter words.
There will never be repeating 5-letter words but two repeating 4-letter words
may occur except at the very end where up to three repeating 4-letter words may
occur. Each TRBV sequence of words whose first two words are 5-letter words and
the very first word is from the sub-list 5wordH can be identified as 32-bit
mode.


4.4 64-bit mode
-------------------------------------------------------------------------------

The 64-bit mode requires a minimum value size of 33 bits. If the value hat less
than 64 bits, zero bits are prepended.

In the 64-bit mode, the value is represented by a sequence of 64-bit patterns,
from the most significant bits to the least significant bits. If there are less
than 64 bits but at least 32 bits left in the value (i.e. 56, 48, 40 or 32
bits), the 32-bit mode is used for the remaining bits. If there are less than
32 bits but at least 16 bits left in the value (i.e. 24 or 16 bits), the 16-bit
mode is used for the remaining bits. Otherwise, if there are only 8 bits
remaining, the 8-bit mode is used.

All patterns are separated by a hyphen-minus '-'. The resulting sequence of
words has a length of (n * 39) + 38 characters.

The resulting sequence of words always consists of 5-letter and 4-letter words.
There will never be more than three repeating 5-letter words and two repeating
4-letter words except at the very end where up to three repeating 4-letter
words may occur. Each TRBV sequence of words whose first two words are exactly
one 5-letter word and one 4-letter (in any order) can be identified as 64-bit
mode.
